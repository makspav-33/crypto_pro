# DigitalVault

Навчальна криптографічна платформа. Реалізовані базова інфраструктура, автентифікація та особистий кабінет.

## Стек і структура

React + TypeScript + Vite + Tailwind CSS; Python + FastAPI; SQLite; PyJWT (HS256); argon2-cffi (Argon2id).

```text
frontend/
  src/App.tsx          # Login, Register, protected layout, Dashboard, Profile
  src/api.ts           # Bearer API client, errors, request timeout
  src/main.tsx
  src/styles.css
  package.json
  package-lock.json
  vite.config.ts
  tsconfig.json
  index.html
backend/
  app/config.py        # Root .env settings
  app/database.py      # SQLite connections and additive users schema
  app/auth.py          # Authentication endpoints and JWT validation
  app/main.py          # FastAPI, CORS, health endpoint
  app/history.py       # User-scoped history API, statistics, metadata persistence
  app/__init__.py
  data/.gitkeep
  tests/test_auth.py   # Isolated real HTTP integration tests
  requirements.txt
.env.example
.gitignore
README.md
```

## Запуск у Windows PowerShell

Потрібні Python 3.11+, Node.js 22.12+ та доступ до npm/PyPI. `npm.cmd` працює без зміни PowerShell execution policy.

Перший запуск, із кореня проєкту:

```powershell
Set-Location D:\crypto_pro
# Лише якщо .env ще немає:
Copy-Item .env.example .env
# Генерація секрету — вставте отримане значення в JWT_SECRET у приватному .env:
python -c "import secrets; print(secrets.token_urlsafe(48))"
```

У `.env` обов’язково встановіть `JWT_SECRET` (щонайменше 32 байти, випадково згенерований). Секрет не має значення за замовчуванням, не зберігається в репозиторії та не передається frontend. `JWT_TTL_MINUTES=15`, дозволений діапазон 1–60 хвилин. Без валідних налаштувань backend відмовиться стартувати.

Backend — термінал 1 (наявне virtual environment):

```powershell
Set-Location D:\crypto_pro
# Тільки якщо backend\.venv ще не створене:
# python -m venv backend\.venv
.\backend\.venv\Scripts\python.exe -m pip install -r backend\requirements.txt
.\backend\.venv\Scripts\python.exe -m uvicorn app.main:app --app-dir backend --reload --host 127.0.0.1 --port 8000
```

Frontend — термінал 2:

```powershell
Set-Location D:\crypto_pro\frontend
npm.cmd install
npm.cmd run build
npm.cmd run dev
```

Відкрийте http://localhost:5173. Backend: http://127.0.0.1:8000; Swagger: http://127.0.0.1:8000/docs.

Кореневий `.env` читається обома застосунками. Після змін перезапустіть сервери. `DATABASE_PATH` відносний до кореня; SQLite-файл створюється під час запуску, увімкнено WAL та foreign keys. Наявні файли не видаляються; таблиця `users` додається через `CREATE TABLE IF NOT EXISTS`.

## API

| Метод | Шлях | Призначення |
|---|---|---|
| GET | `/api/health` | Публічна перевірка стану |
| POST | `/api/auth/register` | JSON: username, email, password; повертає публічного користувача (201) |
| POST | `/api/auth/login` | JSON: email, password; повертає access_token, expires_at, token_type, user |
| GET | `/api/auth/me` | Публічні поля поточного користувача; потрібен Bearer token |
| GET | `/api/auth/token-info` | Перевірені Header, Payload та прихований Signature; потрібен Bearer token |

Username: 3–40 латинських літер, цифр, `_`, `.` або `-`. Email нормалізується до нижнього регістру, унікальність забезпечує SQLite. Пароль: 12–128 символів; зберігається лише Argon2id-хеш. Валідаційні відповіді не віддзеркалюють пароль чи інші введені значення. API не повертає хеші.

JWT містить рядковий `sub` (ID користувача), `name` (username з SQLite), `email` та числові `iat`, `exp`. Сервер перевіряє HS256, підпис, обов’язкові поля, термін дії та існування користувача. Заголовок запиту: `Authorization: Bearer <access_token>`. CORS дозволяє GET/POST/DELETE з http://localhost:5173 та http://127.0.0.1:5173, включно з Authorization і Content-Type.

Токен існує лише у React state: localStorage/sessionStorage/cookies не використовуються. Перезавантаження вимагає входу. Вихід очищає токен і перенаправляє на Login; серверне відкликання JWT не реалізоване, тому раніше скопійований токен залишається дійсним до exp. Автоматичний вихід спрацьовує за таймером, після повернення фокуса та при 401 захищених запитів профілю.

Dashboard показує справжнього користувача та статистику його збережених операцій із SQLite. Crypto Lab, File Encryption та History реалізовані як захищені сторінки.

Інтеграційні тести запускають окремий Uvicorn з тимчасовою SQLite та випадковим секретом, не змінюючи основну БД. ## Запуск одним файлом

Запустіть `D:\crypto_pro\start.bat` подвійним кліком або через `.\start.bat` у PowerShell. Скрипт перевіряє залежності, JWT-конфігурацію та порти 8000/5173, запускає сервери в окремих терміналах і відкриває браузер після готовності обох серверів. Залежності не встановлює, секрет не генерує повторно. Для зупинки натисніть Ctrl+C у кожному серверному терміналі.

Якщо порти зайняті, закрийте попередні сервери. Скрипт не зупиняє наявні процеси. Після ротації секрету перезапустіть усі backend-процеси: старі процеси зберігають попереднє значення у пам’яті. Явно задані змінні середовища процесу мають пріоритет над `.env`; приберіть застарілий JWT_SECRET із середовища, якщо задавали його вручну.

## Crypto Lab та File Encryption

Класичні шифри — виключно навчальні алгоритми. Вони не забезпечують захист конфіденційних даних, не автентифікують ciphertext та не виявляють неправильний ключ. Помаранчевий банер з інтерфейсу прибрано.

Усі маршрути нижче вимагають `Authorization: Bearer <JWT>`. Автентифікація не змінена; користувацька БД не використовується для зберігання операцій або завантажених файлів. Нових залежностей не додано.

| Метод | API | Формат |
|---|---|---|
| POST | `/api/crypto/text/encrypt` | JSON: `algorithm`, `key` (рядок), `text` |
| POST | `/api/crypto/text/decrypt` | Такий самий JSON |
| POST | `/api/crypto/files/encrypt` | Сирі байти UTF-8 файлу; query: `algorithm`, `key`, `filename` |
| POST | `/api/crypto/files/decrypt` | Сирі байти DigitalVault .txt контейнера; ті самі query-параметри |

Приклад текстового запиту:

```json
{"algorithm":"vertical","key":"1324","text":"ABCDEFG"}
```

Відповідь містить `result`, `length`, `rule`, `steps`, `truncated`, `preview_limit`. Значення algorithm: `caesar`, `horizontal`, `vertical`, `combined`. Текст до 10 000 Unicode-символів, включно з порожнім рядком. Візуалізація обмежена першими 120 символами/позиціями кожного кроку, але результат обчислюється повністю. Номер символу рахується за Unicode code points, не за байтами або графемами.

Правила алгоритмів:

- Caesar: англійський алфавіт з 26 літер та український із 33, включно з ґ/є/і/ї; окремий модуль зсуву для кожного алфавіту. Великі літери збережено. Інші символи не змінюються. Ключ — знакове ціле число до 100 цифр; великі та від’ємні значення нормалізуються через modulo. Дешифрування змінює знак зсуву.
- Ключ перестановки — перестановка цифр 1…N, N від 2 до 9. Цифри позначають ранги стовпців: `1324` означає порядок стовпців `1,3,2,4`. Запис тексту завжди рядками шириною N.
- Horizontal: у кожному рядку читаємо стовпці за зростанням рангів. `ABCDEFG` → `ACBDEGF`.
- Vertical: читаємо цілі стовпці згори вниз за зростанням рангів. `ABCDEFG` → `AECGBFD`.
- Combined: horizontal, потім vertical із тим самим ключем. `ABCDEFG` → `AEBFCGD`. Дешифрування виконує обернену vertical, потім обернену horizontal.
- Доповнювальних символів немає. Відсутні клітинки останнього рядка пропускаються. Для зворотного перетворення будується точна обернена перестановка індексів за довжиною ciphertext. Тому навіть пробіли на початку та в кінці не втрачаються. Візуалізація повертає ті самі індекси, що використовуються алгоритмом; під час decrypt вони показують обернене відображення позицій.

Файли:

- Лише `.txt`, суворе декодування UTF-8, оригінал до 1 MiB (1 048 576 байтів). BOM, CRLF, LF, табуляції, Unicode та кінцеві пробіли зберігаються точно; кодування і переноси рядків не нормалізуються.
- Шифрування повертає `.txt` JSON-контейнер: `format=DigitalVault`, `version=1`, `algorithm`, `length`, `key_width`, `ciphertext`. Ключ у контейнер не записується. Під час дешифрування перевіряються формат, алгоритм, довжина та ширина ключа. Для Caesar key_width дорівнює null.
- Контейнер може бути більшим за оригінал через JSON-екранування; upload при decrypt обмежено 8 MiB. Вміст ciphertext після UTF-8 кодування має вкладатися в 1 MiB. Читання тіла запиту обмежене під час отримання потоку.
- Відповідь — `text/plain; charset=utf-8` із `Content-Disposition: attachment`. У frontend створюється тимчасовий Blob URL для завантаження, потім звільняється. На диск сервера файли не записуються. Multipart-парсер не потрібний.
- Для дешифрування використовуйте завантажений контейнер та той самий ключ. Самостійно змінений або неправильний ключ може дати інший текст: навчальні шифри не перевіряють автентичність.

Перевірено відомі відповіді, візуалізацію індексів encrypt/decrypt, український та англійський текст, регістр, пунктуацію, порожній текст/файл, UTF-8/BOM/CRLF, неправильні ключі, пошкоджені метадані, розмір, розширення файлу та відсутній JWT. Наявні auth-тести також пройшли. Frontend production build успішний. Візуальна взаємодія з браузером автоматично не перевірена.

## History та Dashboard

Історія автоматично записується після успішного перетворення тексту або файлу. Статус `success` означає, що сервер обчислив результат (не підтвердження збереження файлу користувачем). Невдалі та неавторизовані запити не додаються. Таблиця `operation_history` створюється адитивно під час старту; наявні користувачі та дані не видаляються. Минулі операції до появи цього модуля відновити неможливо.

Зберігаються лише ID, user_id, UTC created_at, algorithm, operation, data_type, очищена від шляху назва файлу та status. Тексти, вміст файлів, криптографічні ключі, паролі й JWT не записуються в історію. Помилка запису в SQLite не маскується як успіх операції.

Усі History API вимагають Bearer JWT. Власник визначається лише перевіреним сервером токеном; параметра для вибору чужого user_id немає.

| Метод | API | Призначення |
|---|---|---|
| GET | `/api/history` | Власні записи, від нових до старих |
| GET | `/api/history/stats` | Власні підсумки, 7 днів активності, розподіл алгоритмів, 5 останніх записів |
| DELETE | `/api/history/{id}` | Видалення власного запису; 204 або 404 для відсутнього/чужого |
| DELETE | `/api/history` | Видалення всіх власних записів; 204 |

Список повертає `{items,total,limit,offset}`. Query-параметри: `search` (підрядок назви файлу, алгоритму або ID), `algorithm`, `operation=encrypt|decrypt`, `data_type=text|file`, `limit` (1–100, типово 25), `offset` (від 0). У SQLite lower() регістронезалежний пошук стандартно застосовується до ASCII; для української назви використовуйте відповідний регістр. Пошук та фільтри виконуються на сервері й не відкривають записи інших користувачів.

Dashboard використовує `/api/history/stats`: Total Operations, Encryptions, Decryptions, Files Processed, Most Used Algorithm. Нульові значення справжні, без демонстраційних даних. За однакової частоти найбільш уживаний алгоритм обирається за алфавітом ідентифікатора. Графік показує сім календарних днів UTC включно із сьогодні; відображення часу записів у таблиці локальне. Видалення записів змінює статистику: це підсумки збереженої історії, а не незмінні довічні лічильники.

Frontend: `src/Activity.tsx` містить Dashboard, History, таблиці, пошук, фільтри, пагінацію та підтвердження видалення. Дані оновлюються при відкритті сторінки, поверненні фокуса, кнопкою «Оновити» та після видалення. Очищення завжди стосується всієї власної історії, навіть якщо діють фільтри; це явно вказано в підтвердженні. Графіки зроблено через HTML/CSS без нових залежностей; є текстові підписи та підтримка reduced motion.

Перевірки: 9 тестових методів пройдено. Інтеграційні тести використовують окрему тимчасову БД: перевіряють автоматичний запис Text/File Encrypt/Decrypt, відсутність записів для помилок, точні лічильники, фільтри, пагінацію, ізоляцію двох користувачів, захист JWT, DELETE/CORS, збереження після реального перезапуску Uvicorn та перерахунок після видалення/очищення. Наявні auth та cipher тести пройшли. `npm.cmd run build` успішний. Автоматизованого браузерного E2E-прогону немає.

## Оновлення інтерфейсу: мова Цезаря, файли та профіль

Crypto Lab і File Encryption мають явний вибір мови Цезаря: UA (33 літери) або EN (26). Лише літери вибраного алфавіту змінюються, зі збереженням регістру. Решта символів, зокрема літери іншої мови, залишаються незмінними. Для перестановок UA/EN задає контекст мови без нормалізації, фільтрації або зміни математичної логіки. Візуалізація показує лише вибраний алфавіт.

Текстові API приймають `language: "UA" | "EN"` в JSON; файлові API — однойменний query-параметр. Типово UA. Нові Caesar-контейнери записують language та відхиляють дешифрування з іншою мовою (422). Старі файлові контейнери без language автоматично дешифруються за попередніми правилами обох алфавітів — для сумісності з уже створеними файлами. Перестановки не змінювалися.

File Encryption: доступний із клавіатури вибір одного TXT-файлу, Drag & Drop, підсвічування, назва/розмір, видалення вибору, індикатор обробки й коротка анімація успіху. Перевіряються розширення та розмір; обмеження й UTF-8 перевірка на сервері збережені. Анімації враховують prefers-reduced-motion.

Окремого пункту Profile в навігації немає. Нижній блок користувача — звичайне посилання на #profile, доступне через Tab/Enter, з hover/focus/active оформленням. Logout залишився окремою кнопкою, JWT-логіка не змінена.

Останні перевірки: 11/11 backend-тестів успішні, включно з UA/EN round-trip для тексту та UTF-8 файлів, незмінністю чужого алфавіту, невідповідністю мови контейнеру, сумісністю старих контейнерів, регресіями auth/history/інших шифрів. TypeScript та production build успішні. Автоматизованого браузерного E2E-прогону для drag/drop, клавіатури та різних ширин екрана в цьому середовищі немає.

## Очищення UX та автоматичний вхід

Після успішного POST /api/auth/register frontend одразу виконує POST /api/auth/login із введеними даними, очищає форму, встановлює чинну сесію у React state та переходить на Dashboard. При помилці реєстрації Login не викликається. Якщо акаунт створено, але запит входу не вдався, показується окреме повідомлення з пропозицією Sign In. При виході зі сторінки під час запиту пізня відповідь не створює сесію. Пароль та токен у browser storage не записуються; перезавантаження, як і раніше, вимагає повторного входу.

З інтерфейсу прибрані декоративний футер, технічні банери та повторені заголовки/підписи. Logout залишено лише в Sidebar. Profile показує аватар, username, email, дату реєстрації та статус сесії; безпечні JWT-поля перенесені у закритий за замовчуванням JWT Details. Повного JWT або серверного секрету в ньому немає.

Crypto Lab: початковий текст та ключ збережені, кроки згортні, довгі повторні пояснення прибрані, проміжний результат залишається лише для багатокрокових алгоритмів. Кінцевий результат і кнопка копіювання відображаються один раз. UA/EN та анімований вибір файлу збережені. Інструкція для розшифрування контейнера, попередження про неправильний ключ, помилки й підтвердження очищення історії залишені.

Перевірки цього етапу: 11 backend-тестів успішні; TypeScript і Vite build успішні. Додано необов’язковий браузерний smoke-сценарій без нових пакетів:

```powershell
Set-Location D:\crypto_pro
node frontend/tests/ui-smoke.mjs
```

Потрібен встановлений Chrome (або CHROME_PATH до Edge/Chrome). Сценарій запускає окремі сервери на вільних портах, тимчасову SQLite та окремий headless-профіль браузера; користувацьку БД не змінює. У цьому середовищі прогін Chrome/Edge зупиняється на тайм-ауті CDP Runtime.enable, тому браузерні сценарії не підтверджені. Захисні параметри не вимикалися. Тимчасові тестові артефакти залишаються у системній temp-папці, шлях виводиться після прогону.

## Crypto Terminal

Оформлення оновлено зі збереженням структури навігації, сітки статистики та графіків. Основні кольори: #0B1120, #111827, #38BDF8, #8B5CF6, #22C55E, #E5E7EB. Моноширинний шрифт застосований до технічних значень, текстових панелей, ключа, JWT та цифр статистики. Додані INPUT/OUTPUT, стримані hover/focus-ефекти, блакитний індикатор активного меню; анімації враховують reduced motion.

У Profile додана картка «Безпека сесії» (`SessionSecurity.tsx`): залишок часу в хвилинах/секундах оновлюється щосекунди та після повернення фокуса, прогрес рахується від перевірених сервером iat/exp. Це лише відображення — логіка завершення сесії не змінена. Закриті «Деталі JWT» показують тільки Header і Payload з підсвічуванням JSON; повний токен і секрет не відображаються.

Після обробки файлу залишається доступна кнопка повторного завантаження результату. Початкове автоматичне завантаження збережено; Blob URL звільняється при зміні введення або виході зі сторінки. Формат контейнера та криптографічні операції не змінені.

Перевірки: TypeScript/Vite build успішний, усі 11 backend-тестів пройшли. Окремо через server render перевірено формат 01:05, залишок 65%, 00:00 та 0% після завершення, закриті JWT-деталі. Безперервний таймер і адаптивність в інтерактивному браузері автоматично не перевірені. Зміни backend і користувацької SQLite не виконувалися. Редагування профілю й зміна пароля в поточному API не реалізовані; цей етап їх не додає.

## JWT-дані користувача та спільний вибір мови

Login формує підписаний HS256 JWT з sub, name, email, iat та exp. Name береться з наявного поля users.username (окремої колонки імені немає), email — з users.email. Role не додається; схему SQLite не змінено. /api/auth/token-info повертає лише ці перевірені claims. Візуальна картка Payload відображає тільки sub/name/email; iat/exp продовжують використовуватись таймером і перевіркою строку дії. Header, Signature й механізм авторизації не змінені.

Повторний Login читає актуальні поля користувача з БД. Уже виданий JWT не змінюється після оновлення облікових даних: потрібна повторна авторизація. Старі токени без name/email дійсні до exp; їхній Payload не підміняється даними з БД. Щоб побачити нові поля, вийдіть і увійдіть знову. Поточний етап не додає відсутні API редагування профілю.

LanguageSelector.tsx — спільний контроль UA/EN для поточних чотирьох текстових шифрів у лабораторії та файловому модулі. Зміна мови очищає застарілий результат, зберігає введений текст і ключ та передається в API. Цезар використовує вибраний алфавіт як раніше. Перестановки працюють з довільними Unicode-символами: мова — контекст введення, без видалення символів, нормалізації, зміни індексів чи вимоги відповідності алфавіту. Тому для однакових тексту/ключа ciphertext перестановки однаковий у UA та EN. Формат файлових контейнерів не змінений, language перестановкам для дешифрування не потрібний. Для майбутніх нетекстових алгоритмів перемикач підключається лише за потреби.

Premium-оформлення уточнено: спільні мовні кнопки, navy/graphite поверхні, cyan/violet акценти, рамки результату, панелі JWT та адаптивні стани полів. Немає нових бібліотек чи фіктивних даних.

Перевірки: 13 backend-тестів успішні. Нові сценарії перевіряють claims із реальної тестової SQLite, актуалізацію після зміни username/email і повторного входу, сумісність старих JWT, UA/EN для текстових та файлових перестановок із Ґ/Є/І/Ї, CRLF і пробілами. Усі попередні auth/history/cipher тести також пройшли. TypeScript/Vite build успішний. Server-render перевірив Payload лише з sub/name/email, приховування підпису, таймер, закриті деталі та обидва стани LanguageSelector. Інтерактивний браузерний E2E-прогін не підтверджено через попередні обмеження CDP у середовищі.
